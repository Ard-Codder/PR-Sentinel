# PR Sentinel

Локальный агент смотрит открытые GitHub PR, где вы назначены ревьюером, отправляет diff в OpenAI-совместимую модель и публикует один комментарий. Новый коммит обновляет тот же комментарий.

По умолчанию включён безопасный режим: ревью считается и пишется в лог, в GitHub ничего не отправляется.

## Что нужно

- macOS и [uv](https://docs.astral.sh/uv/). Если `uv` не в `PATH`, выполните `source "$HOME/.local/bin/env"`.
- Python 3.12 подтянет сам `uv`. Системный Python 3.9 для запуска не используется.
- LM Studio с моделью `qwen3-coder-30b-a3b-instruct`. На этой машине отвечает `http://127.0.0.1:1234/v1`. Адрес `192.168.3.5:1234` недоступен.
- Fine-grained GitHub PAT.

## Права токена

Достаточно одной репозиторной роли: **Pull requests: Read and write**. Выдайте её только тем репозиториям, которые приложение должно видеть.

Metadata: Read GitHub включает сам, отдельно его добавлять не нужно. Contents, Issues, Administration и Actions не нужны. Патч приходит из `GET /pulls/{n}/files`, комментарий PR создаётся и обновляется как issue comment, и эта роль pull requests такое действие уже разрешает.

Классический scope `repo` шире, чем нужно для этого сценария.

## Установка

```bash
cd /path/to/pr-sentinel
source "$HOME/.local/bin/env"   # если uv ещё не в PATH
uv sync --group dev
cp .env.example .env
```

В `.env` укажите `GITHUB_TOKEN`. `GITHUB_REPOS` — список `owner/repo` через запятую. Если список пустой, берутся репозитории, уже доступные токену, не больше `MAX_REPOS`.

`DRY_RUN=true` стоит по умолчанию и в коде, и в примере конфига. Публикация включается только так:

```bash
DRY_RUN=false
```

## Запуск

Один проход:

```bash
uv run pr-sentinel once
```

Регулярный опрос, пауза `POLL_INTERVAL_SECONDS` (по умолчанию 120):

```bash
uv run pr-sentinel loop
```

В безопасном режиме готовый текст комментария попадает в лог. Повторный проход того же SHA модель заново не вызывает. После `DRY_RUN=false` этот SHA публикуется.

Состояние лежит в SQLite (`DATABASE_PATH`, по умолчанию `./data/state.db`):

- проверка конкретного коммита: `repo + номер PR + SHA`;
- `comment_id` хранится отдельно на PR и не сбрасывается при новом SHA.

`skipped` означает, что в PR не осталось файлов для анализа. Такой SHA повторно не берётся. Ошибка GitHub, ошибка модели и неразобранный ответ получают статус `error` и повторяются на следующем проходе.

## Тесты

Без сети и без токена:

```bash
uv run pytest
```

Один живой вызов LM Studio, в обычный прогон не входит:

```bash
uv run pytest tests/test_live_llm.py -o addopts= -m integration
```

## Ограничения

- Комментарий один на весь PR, без inline-заметок на строках diff и без approve/request changes.
- Замечание принимается только для строки нового файла, которая в diff начинается с `+`. Удаления и неизменённый контекст в комментарий не попадают.
- Большой diff режется на последовательные части, не больше `MAX_CHUNKS` (по умолчанию 4). Очереди нет.
- За один проход обрабатывается не больше `MAX_PRS_PER_CYCLE` PR, строго по очереди.
- Search API не используется.
